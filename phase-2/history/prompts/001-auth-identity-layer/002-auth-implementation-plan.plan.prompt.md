## Prompt

/sp.plan Authentication & User Identity Layer

Objective:
Create a complete, secure authentication flow that establishes trusted user identity across a Next.js frontend and FastAPI backend using Better Auth and JWTs, without any manual coding.

Planning requirements:
- Follow strictly: Specification → Plan → Tasks → Implementation
- Produce a step-by-step implementation plan that an agent can execute deterministically
- Each step must have a clear purpose, inputs, and outputs
- No code implementation yet — planning only

Plan scope:
1. Frontend authentication setup
   - Initialize Better Auth in Next.js App Router
   - Configure credential-based signup and signin
   - Enable JWT plugin to issue signed tokens
   - Store JWT securely on client (session-based handling)

2. Environment & secrets strategy
   - Define shared JWT secret usage
   - Configure environment variables for frontend and backend
   - Ensure no secrets are hardcoded

3. Frontend API request pipeline
   - Design API client strategy
   - Attach Authorization: Bearer <JWT> header to every request
   - Handle missing or expired token cases

4. Backend JWT verification layer
   - Design FastAPI middleware or dependency
   - Extract Authorization header
   - Verify JWT signature using shared secret
   - Decode token payload to retrieve user identity

5. Request authorization enforcement
   - Ensure authenticated user identity is available in request context
   - Reject unauthorized or invalid requests with 401
   - Define standard error responses for auth failures

6. Validation & verification strategy
   - Define how authentication success is verified
   - Define test cases for valid, invalid, and missing tokens
   - Ensure compatibility with downstream task APIs

Constraints to respect:
- Use Better Auth only for authentication
- Use JWTs as the sole backend authorization mechanism
- No backend session storage
- No manual code edits; all outputs generated by agent
- Must be compatible with Next.js 16+ and FastAPI

Deliverables:
- Ordered implementation steps
- Clear task boundaries suitable for agent execution
- Explicit handoff points to Spec 2 (Backend API)
- Auth layer ready for reuse by all secured endpoints

Completion criteria:
- Plan is complete, deterministic, and executable by an AI coding agent
- No ambiguity in auth flow or identity propagation
- Fully aligned with sp.constitution and sp.specify
